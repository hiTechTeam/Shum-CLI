# Подпись Shum CLI на macOS

## Создание сертификата вручную

1. Откройте «Связку ключей» и выберите связку «Вход» (`login`).
2. В меню «Связка ключей → Ассистент сертификации → Создать сертификат»
   укажите имя **Shum CLI Signing**.
3. Тип идентификации: **Самоподписанный корневой сертификат**.
   Тип сертификата: **Подпись кода**. Включите замену настроек по умолчанию.
4. Выберите срок действия, например 3650 дней, RSA 2048 бит или больше.
   Оставьте применение «Подпись» и расширение «Подпись кода».
   Дополнительные имена Subject Alternate Name не нужны.
5. Сохраните в `login`. В «Мои сертификаты» должна появиться запись с закрытым
   ключом. Пароли и разрешения системных диалогов вводит владелец Mac.

[Инструкция Apple](https://support.apple.com/en-ca/guide/keychain-access/kyca8916/mac).
Не пересоздавайте сертификат для каждого выпуска: новый сертификат означает
новую личность приложения. Закрытый ключ не экспортируется скриптом упаковки.
Настройки системного доверия скрипт не меняет.

## Упаковка

```sh
python3 scripts/package_macos.py --binary /путь/к/проверенному/shum --output /путь/к/новому/каталогу
python3 scripts/verify_macos_package.py /путь/к/новому/каталогу/Shum-CLI-VERSION-macOS-arm64-unsigned.pkg
```

Версия в Info.plist берётся из Cargo.toml. Подписывается весь Shum.app;
в архив попадает бандл целиком. Скрипт читает только публичный сертификат по имени,
вычисляет его SHA-1 и выбирает точную identity для codesign.
Явное designated requirement:

```text
designated => identifier "org.shum.cli" and certificate leaf = H"SHA1_СЕРТИФИКАТА"
```

`--timestamp=none` исключает сетевой запрос за timestamp. Подпись контейнера
Installer и нотарификация являются отдельными этапами. Локальный сертификат
не даёт доверия Apple на компьютерах пользователей.

## Проверка двух сборок

Упакуйте два разных проверенных бинарника тем же сертификатом в разные каталоги.
SHA-256 исполняемых файлов должны различаться. Для обоих бандлов выполните:

```sh
codesign --verify --strict /путь/к/Shum.app
codesign -dr - /путь/к/Shum.app
```

Требование должно совпадать, содержать идентификатор и отпечаток сертификата,
не содержать `cdhash`. Сохранение одного requirement само по себе не доказывает
сохранение разрешения Bluetooth на обновлении.

## Проверка обновления на Mac

После согласования выпуска установите N через Homebrew, разрешите Bluetooth,
отправьте и получите сообщение. Зафиксируйте `shum --json status` (`build.version`,
`build.sha256`) и PID из daemon.json. Обновитесь до N+1 и запустите CLI.
Проверьте новую версию, новый SHA-256 и PID, обмен сообщениями, отсутствие повторного
запроса Bluetooth. При включённом автозапуске ProgramArguments должен использовать
`$(brew --prefix)/opt/shum/Shum.app/Contents/MacOS/shum`.

Если macOS снова запрашивает Bluetooth, результат проверки отрицательный.
Его нужно сообщить прямо; сброс TCC, изменение базы разрешений или системного
доверия не входят в эту проверку. Переход со старой ad hoc подписи на сертификат
может запросить разрешение один раз; это отличается от проверки двух выпусков,
уже подписанных одним сертификатом.

## Проверка удаления

```sh
shum daemon --uninstall
brew uninstall shum
launchctl list
ls ~/Library/LaunchAgents
```

Служб и plist Shum больше нет, профили, ключи и сообщения остаются в
`~/Library/Application Support/org.Shum.Shum` (либо выбранном `--data-dir`).
Повторное удаление службы завершается успешно. Ручная очистка, если формулу
удалили раньше, описана в README.
