# Протокол и ближайшие этапы CLI

Сверено 9 октября 2026 с Shum-Protocol `8e02c9d`. Переход с `fc74785`
меняет только README и спецификацию; разделы 01–09 и `vectors/` не изменены.
Ядро закрепляет `126498b`: те же документы плюс согласованный файл MIT LICENSE.
CLI использует Shum-Core `93df231` для всех четырёх пакетов. Эта ревизия
разрешает одинаковые имена локальных профилей и выбирает их только по ID;
байты протокола не изменены.

## Что работает сейчас

CLI подключает одну закреплённую ревизию Shum-Core для протокола, SQLite,
Nostr и Bluetooth. Ядро реализует черновик v1, описанный разделами 01–09,
с согласованной строгой проверкой Ed25519 и защитой от повторов Noise.
Приглашения, переписка, история, доставка, прочтение, набор текста,
несколько независимых профилей и macOS Bluetooth доступны сейчас.
Несколько профилей не означают несколько устройств одного профиля.

Приоритет текущего CLI: надёжная работа на macOS Apple Silicon, готовый
подписанный бандл, обновление службы без потери очереди и штатное удаление.
Intel не задерживает этот этап. Универсальная сборка уже подготовлена и
проверена через Rosetta; настоящего Intel Mac в проверке не было.

## Куда движется первая стабильная версия

| Часть | Решение в спецификации | Состояние реализации |
|---|---|---|
| Общая реализация | Протокол один раз в Rust, клиенты подключают ядро | CLI уже использует ядро; переход iOS через UniFFI впереди |
| Устройства, раздел 10 | Равноправные устройства, общие ключи профиля, отдельные ключи устройств, взаимная привязка по QR | Форматы, метки подписей и примеры ещё нужны; `link`/`unlink` недоступны |
| История и настройки | При привязке история за 30 дней; настройки синхронизируются автоматически, история вручную по Bluetooth | Самоканал и `sync` ещё не реализованы |
| Отвязка | Подписанный реестр устройств, смена Nostr-ключа и сетевых пропусков | Нужны форматы и сценарии отзыва доступа |
| Релеи, раздел 11 | Ящик получателя в карточке, ревизии конфигурации, подтверждения, старые релеи read-only до 30 дней | Сейчас только настройки релеев конкретного CLI-профиля; новый формат записи впереди |
| Сети релеев | Приглашения, NIP-42 и членство на уровне профиля | Формат приглашения и пропуска ещё не определён |
| Совместимость, раздел 12 | Неизвестные поля сохраняются, возможности согласуются, подписанные структуры имеют версию | Нужен общий контракт и тестовые примеры |
| Перенос профилей | Сохранить три ключа, Shum ID и историю черновика | Требование для будущих миграций; не заменять существующий профиль новым |

Раньше устройства назывались v2. Теперь они входят в первую v1 stable.
Текущий CLI остаётся превью черновика, а не объявлением готовности v1 stable.

## Порядок следующей работы

1. CLI 0.1.6 и tap опубликованы с согласия владельца, реальное обновление
   Homebrew, замена службы и доставка с iPhone в обе стороны проверены.
   Проверить Bluetooth при следующем сертификатном обновлении.
   [Проверка поставки](release-verification.md).
2. Зафиксировать решения и wire-форматы в Shum-Protocol: каноническую карточку
   с меткой домена, стандартный NIP-44, общий код безопасности, привязку,
   самоканал, реестр устройств и ревизии релеев. Предложения в разделе 12
   ещё не являются разрешением менять байты текущей переписки.
3. Реализовать форматы и миграции в Shum-Core, добавить общие тестовые примеры,
   затем подключить новую ревизию ядра в CLI и остальных клиентах.
4. Провести приёмку на настоящих клиентах: привязка в обе стороны, доставка
   всем устройствам, отзыв доступа, синхронизация, изоляция профилей и расширение.

Открыты выборы шифрования для нескольких устройств, канала привязки,
привязки без камеры, объединения устройств рядом, слияния релеев,
ratchet, подписи счётчика пересылок и изоляции push. Их нельзя подменять
самостоятельно выбранными форматами в CLI.

Спецификация: [устройства](https://github.com/hiTechTeam/Shum-Protocol/blob/8e02c9d/spec/10-devices.md),
[релеи](https://github.com/hiTechTeam/Shum-Protocol/blob/8e02c9d/spec/11-relays.md),
