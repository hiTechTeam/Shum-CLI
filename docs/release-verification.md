# Проверка опубликованного CLI 0.1.6

9 октября 2026, Mac Apple Silicon, macOS 15.6.1.

## Поставка и исходники

Опубликованы [CLI 0.1.6](https://github.com/hiTechTeam/Shum-CLI/releases/tag/v0.1.6)
и [пакеты tap](https://github.com/hiTechTeam/homebrew-shum/releases/tag/v0.1.6).
В обоих выпусках пять одинаковых файлов; их серверные SHA-256 совпадают
с локальными. Публичный `releases/latest/download/shum-macos-universal.tar.gz`
проверен загрузкой и сверкой SHA-256. install.sh доступен в main CLI.

- Исходники бинарника и тег v0.1.6: CLI `aa8030b`.
- Ядро: `4020dfd25bcbfd7a60040c435b065665c8d11684`.
- Протокол: `126498b3e148b801734aa85b2f5587967adf5d91`, документы `8e02c9d`.
- Формула tap: `85d4829`. Архив выпуска и тег CLI не подменялись.

Первый настоящий brew upgrade обнаружил ошибку формулы: Homebrew убирает
единственную внешнюю папку архива. Формула исправлена, устанавливает Contents
из вложенного либо распакованного корня в Shum.app. Повторное обновление успешно.
Тот же исправленный шаблон сохранён в генераторе пакетов CLI.
Автоматический CI остаётся выключенным.

## Реальное обновление и удаление службы

`brew upgrade shum` установил 0.1.6 на Mac владельца. Бинарник в установленном
бандле совпадает с опубликованным; строгая проверка подписи проходит. При первом
вызове CLI служба автоматически сменила PID и версию 0.1.5 на 0.1.6,
Shum ID сохранился. В статусе остались два контакта и 71 сообщение.
Bluetooth перешёл в состояния advertising и scanning. Владелец подтвердил:
macOS показала новый запрос Bluetooth, доступ разрешён; сообщения между
обновлённым CLI и iPhone доходят в обе стороны.

Отдельно два сертификатных бандла проверены с реальными LaunchAgents:
после переключения opt на новый бандл и удаления старой папки Cellar следующая
команда заменяет службу, сохраняя профиль и историю. Homebrew в этом сценарии
моделировался; реальный brew upgrade проверен отдельно, как описано выше.

`macos_service_lifecycle.py` выполнен с установленным Homebrew-бандлом:

```text
PASS real launchctl bootstrap/bootout, KeepAlive=false, two profiles, idempotent uninstall
PASS profile registry, key files and encrypted database records preserved
PASS packaged app reused directly; LaunchAgent executable outside Cellar
Only disposable profiles uninstalled; installed Homebrew formula unchanged
```

После `daemon --uninstall` нет тестовых служб в launchctl и их plist в
~/Library/LaunchAgents. Ключи, реестр профилей и зашифрованные записи базы
совпадают с состоянием до удаления. Повторное удаление и удаление для отсутствующего
каталога завершаются успешно. Проверка ограничена временными профилями:
службы владельца и установленная формула сохраняются.

## Результаты приёмки установщика 1–6

1. Две архитектуры и постоянное требование подписи: PASS.
2. Rosetta, версия и релейный сценарий: PASS; настоящий Intel не проверен.
3. Чистая учётная запись, Gatekeeper и единственный запрос Bluetooth:
   не проверены. Временный HOME тестов не является чистой учётной записью macOS.
4. Обновление скриптом: PASS на фикстурах. Отсутствие повторного запроса Bluetooth
   между двумя реально опубликованными сертификатными версиями не проверено.
5. Архив с неверным SHA-256 не ставится: PASS на фикстуре.
6. Удаление файлов ~/.local с сохранением данных: PASS на фикстурах.
   Удаление реальных LaunchAgents: PASS на временных профилях установленного CLI.

Переход с ad hoc 0.1.5 на сертификатную 0.1.6 меняет идентичность подписи.
При этом переходе macOS действительно запросила Bluetooth заново.
Отсутствие повторного запроса при следующем сертификатном обновлении
пока не подтверждено. Самоподписанный сертификат не является Developer ID;
pkg не подписан и не нотарифицирован Apple. Работа Gatekeeper без предупреждений
на другом Mac не подтверждена. Обходы этих проверок не применялись.

Текущий выпуск реализует черновик v1. Разделы 01–09 и тестовые примеры протокола
не менялись; будущие устройства и синхронизация v1 stable ещё впереди.
