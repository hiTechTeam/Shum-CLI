# Подробная инструкция CLI

Клиент Shum для терминала: команды, TUI, профили, системная служба и установка.
Общее ядро и адаптеры находятся в отдельном
[Shum-Core](https://github.com/hiTechTeam/Shum-Core). CLI подключает их как
Git-зависимости по одной закреплённой ревизии в Cargo.toml и Cargo.lock.
Версия клиента 0.1.6 выпускается независимо от версии ядра.

## Состояние

Работают интернет-переписка через Nostr, push-запросы, несколько профилей,
приглашения и QR, история, отметки доставки и прочтения, реакции и TUI.
На macOS с реальным iPhone проверены Bluetooth-обнаружение, приглашение,
сообщения в обе стороны и прочтение. Полная интернет-приёмка с iPhone,
APNs и проверка на настоящих Linux/Windows ещё не завершены.
GATT-сервер на Linux/Windows и фото-аватары не реализованы. Несколько устройств
одного профиля, синхронизация и релеи профиля входят в будущую v1 stable;
сейчас CLI реализует черновик v1. [Состояние протокола](protocol-status.md).

Аватары, QR, цвета и интерфейс принадлежат этому репозиторию. Ядро не зависит
от CLI. В Terminal компактные портреты рисуются фоном ячеек без настройки
шрифта; Warp получает PNG. Индикатор «печатает…» виден в списке чатов.
Примеры аватаров v1 находятся в `tests/fixtures` с ревизией и SHA-256 источника.
История пакета CLI сохранена из прежнего workspace Shum-Core.

Проверки клиента включают криптографию, приглашения, локальный релей,
замену службы, TUI и сохранность профилей. Подписанный пакет, стабильный путь
службы и установка/обновление/удаление проверены на временных профилях.
Результаты: [служба и подпись](service-verification.md),
[пакет и установщик](intel-install-verification.md).
Автоматический CI отключён; номера версий и публичные пакеты при переносе
не меняются.

Свежие результаты синхронизации и проверки: [sync-verification.md](sync-verification.md).
Опубликованный 0.1.6, реальное обновление Homebrew и проверки удаления:
[release-verification.md](release-verification.md).

Документация ядра: [API](https://github.com/hiTechTeam/Shum-Core/blob/main/docs/core-api.md)
и [хранилище](https://github.com/hiTechTeam/Shum-Core/blob/main/docs/storage.md).

## Установка готового CLI

Готовый CLI 0.1.6 доступен для **macOS 15+, Apple Silicon и Intel**:

```sh
brew install hitechteam/shum/shum
shum
```

Установщик `.pkg` и контрольные суммы доступны в
[публичных выпусках](https://github.com/hiTechTeam/homebrew-shum/releases).
Это preview без подписи Developer ID и нотарификации Apple.
Профили и переписка сохраняются при обновлении. Подробности и состояние остальных
платформ: [distribution.md](distribution.md).

### Установка без Homebrew

Установка и обновление выполняются одной командой:

```sh
curl -fsSL https://raw.githubusercontent.com/hiTechTeam/Shum-CLI/main/install.sh | sh
```

Подписанный бандл ставится в `~/.local/share/shum`, команда в `~/.local/bin/shum`.
Если каталог команд отсутствует в PATH, установщик печатает нужную команду;
файлы оболочки не меняются. Установка рядом с Homebrew отклоняется: используйте
`brew upgrade shum`. Повторный запуск проверяет SHA-256, переключает стабильную
ссылку на новую версию и мягко обновляет активные службы всех профилей.
Неактивные профили не запускаются. Старые бандлы сохраняются до удаления установки.

Удаление установки без Homebrew:

```sh
curl -fsSL https://raw.githubusercontent.com/hiTechTeam/Shum-CLI/main/install.sh | sh -s -- --uninstall
```

Или выполните `sh install.sh --uninstall` из сохранённого скрипта.
Сначала вызывается `shum daemon --uninstall`, затем удаляется установка из `~/.local`.
Профили, ключи и переписка сохраняются; каталог данных указан ниже в разделе удаления.
Под Rosetta проверены Intel CLI, приглашения, сообщения, квитанции и перезапуск
с сохранением очереди. На настоящем Intel Mac проверка пока не проводилась;
Rosetta не заменяет её.
Запуск без предупреждений Gatekeeper и единственный запрос Bluetooth на чистой
учётной записи пока не подтверждены. Самоподписанный сертификат не является
Developer ID и не заменяет нотарификацию Apple.

## Получение исходников и проверка

Cargo получает ядро по закреплённой Git-ревизии;
соседняя папка Shum-Core и общий workspace не требуются.

```sh
git clone https://github.com/hiTechTeam/Shum-CLI.git
cd Shum-CLI
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --all -- --check
```

На этом Mac rustup установлен через Homebrew. Его команды доступны после:

```sh
export PATH="/opt/homebrew/opt/rustup/bin:$PATH"
rustc --version
cargo --version
```

Это меняет PATH только в текущем терминале; настройки shell автоматически
не редактируются.

Установка клиента:

```sh
cargo install --path . --locked
```

На этом Mac установленный бинарник доступен по `~/.cargo/bin/shum`.
Чтобы команды `shum`, `shum chats` и остальные находились в новых вкладках
Terminal и Warp, добавьте в `~/.zshrc`:

```sh
if [[ -d "$HOME/.cargo/bin" && ":$PATH:" != *":$HOME/.cargo/bin:"* ]]; then
  export PATH="$HOME/.cargo/bin:$PATH"
fi
```

Затем откройте новую вкладку терминала. Для уже открытой вкладки достаточно:

```sh
export PATH="$HOME/.cargo/bin:$PATH"
rehash
shum chats
```

`zsh: command not found: shum` означает, что shell не нашёл бинарник в PATH.
Проверить путь можно командой `command -v shum`.

Можно обойтись без изменения PATH:

```sh
~/.cargo/bin/shum init
~/.cargo/bin/shum
```

Первый `shum` сам откроет создание профиля, если профилей ещё нет.
`shum init` открывает тот же мастер: имя, прозрачный пиксельный аватар
(`r` другой, Enter подтвердить), сохранение ключей и проверка чтения
зашифрованной базы. Esc до подтверждения отменяет создание без записи профиля.
`init --name <имя>` остаётся неинтерактивной командой. Для сервера без
него: `shum init --name server --headless` (Unix, ключи в файле 0600).
При закрытии TUI служба продолжает принимать сообщения; остановить её:
`shum daemon --stop`. Для автозапуска после входа: `shum daemon --install`.

Каталог данных macOS: `~/Library/Application Support/org.Shum.Shum`.
Точный путь показывает `shum status`. Для отдельного теста:
`shum --data-dir /tmp/shum-demo init --name Test --headless`.
Все команды принимают `-p <имя или ID>`, `--json`, `--ascii` и `--data-dir`.
Вне терминала TUI не открывается; `open --json` выдаёт обновления сообщений
построчно до Ctrl+C. Ники с пробелами нужно заключать в кавычки.

Terminal.app автоматически использует палитру 256 цветов. Цветной TUI задаёт
фон и цвет текста явно, поэтому остаётся читаемым и в светлой теме терминала.
Warp получает PNG через прямые размещения Kitty с явным удалением картинок
при смене экрана. iTerm2 и WezTerm используют протокол iTerm2; Kitty использует
свой графический протокол. Терминалы без графического протокола автоматически
рисуют персонажа цветным
фоном ячеек: сетка 12×12 занимает 24×12 ячеек. Компактный портрет строится из тех
же форм, цветов и параметров seed, а каждая черта лица занимает минимум один
пиксель. Он сохраняет голову и плечи без уменьшения готового растра. Символы
полублоков не используются, поэтому специальных шрифтов, интервалов и профилей
Terminal не требуется. В узких окнах портрет скрывается, оставляя место тексту.
Перед размещением прозрачного PNG в Warp закрашивается весь фон под картинкой.
В маленьком окне символьные аватары скрываются, чтобы оставить место переписке.
Прозрачные пиксели сохраняют фон UI; генератор персонажей не меняется.
В режиме `--ascii` аватары и цвета по-прежнему отключены.

Обычные команды тоже используют цвета из макетов: `shum chats` выделяет
людей рядом и непрочитанные сообщения зелёным, приглашения жёлтым,
подсказки команд голубым. `shum about` показывает пиксельный логотип,
сведения о системе и образцы палитры. В Terminal.app используется 256 цветов,
в Warp — RGB. Команды сохраняют фон терминала и сбрасывают цвет после вывода.
При перенаправлении в файл, с `--json`, `--ascii`, `NO_COLOR=1` или `TERM=dumb`
цветовых кодов в выводе команд нет.

Проверка цветного вывода в PTY с временным профилем и локальной подставной
службой (без Keychain, Bluetooth и внешних релеев):

```sh
python3 tests/manual/command_colors.py ~/.cargo/bin/shum
```

Bluetooth включён по умолчанию у обычных профилей. `init --headless`
создаёт профиль с выключенным Bluetooth; включить его явно можно командой
`shum --bluetooth status`, выключить: `shum --no-bluetooth status`.
Оба флага сохраняют настройку выбранного профиля. На macOS разрешите доступ
к Bluetooth приложению **Shum** в системном запросе. Служба запускается через
Launch Services как фоновое приложение с собственным описанием доступа
(`NSBluetoothAlwaysUsageDescription`). Поэтому разрешение относится к Shum,
а запуск CLI не зависит от наличия этого описания у Warp или другого терминала.
Если ранее отказали: «Системные настройки → Конфиденциальность и безопасность
→ Bluetooth → Shum», затем `shum --bluetooth status`.
Без адаптера интернет-переписка продолжает работать.
По Bluetooth показывается только профиль, выбранный через `profile use`;
фоновые службы остальных профилей продолжают работу через релей.
При запуске CLI сравнивает версию и SHA-256 с работающей службой. После обновления
он штатно останавливает старую службу, сохраняет очередь и запускает новую.
Первое обнаружение занимает несколько секунд; вкладка «Рядом»
обновляется автоматически. Расстояние приблизительное, по RSSI; если сигнал
недоступен в текущей роли GATT, число не показывается.

Для сборки Bluetooth на macOS нужны Xcode Command Line Tools (`xcrun swiftc`).
Небольшой встроенный Swift-процесс выполняет только CoreBluetooth I/O;
ключи, проверка личности, шифрование и сообщения остаются в Rust.
Начиная с 0.1.6 служба запускается из готового `Shum.app`,
подписанного сертификатом `Shum CLI Signing`, без копирования и переподписи.
Homebrew устанавливает бандл в свой префикс, а `bin/shum` ссылается на бинарник
внутри. LaunchAgent использует стабильный путь
`$(brew --prefix)/opt/shum/Shum.app/Contents/MacOS/shum`.
Установка скриптом использует `~/.local/share/shum/Shum.app/Contents/MacOS/shum`,
также через стабильную ссылку.
Для сборок через Cargo остаётся локальная ad hoc копия
`services/<hash>/Shum.app` в каталоге данных; такая подпись может снова вызвать
запрос разрешения после пересборки. CLI ждёт запуска службы до минуты.
Автозапуск при входе включается через `shum daemon --install`; `KeepAlive=false`.
Самоподписанный сертификат не заменяет Developer ID или нотарификацию.
Инструкция по сертификату и проверке обновления: [macos-signing.md](macos-signing.md).

### Удаление службы и приложения

```sh
shum daemon --uninstall
brew uninstall shum
```

Первая команда штатно останавливает службы всех профилей, выгружает и удаляет
их LaunchAgents и удаляет кэш локальных `Shum.app`. Она не открывает хранилище
ключей и сохраняет профили, ключи и переписку. Повторный запуск безопасен.
Без `--data-dir` учитываются также каталоги всех Shum LaunchAgents этого пользователя.
С `--data-dir /каталог` команда ограничена этим каталогом, независимо от `--profile`.
После удаления службы следующая обычная команда CLI снова может запустить её.

Данные macOS: `~/Library/Application Support/org.Shum.Shum`.
Если использовался `--data-dir`, данные лежат в указанном каталоге.
Чтобы стереть всё, сначала остановите службы, затем вручную удалите именно этот
каталог данных. Профили с ключами в macOS Keychain дополнительно требуют ручного
удаления принадлежащих им объектов Shum в «Связке ключей». Сертификат выпуска
`Shum CLI Signing` не относится к ключам профилей.

Если формула уже удалена, для **каждого** файла
`~/Library/LaunchAgents/org.shum.cli.<ID_профиля>.plist` выполните:

```sh
launchctl bootout "gui/$(id -u)" "$HOME/Library/LaunchAgents/org.shum.cli.<ID_профиля>.plist"
rm "$HOME/Library/LaunchAgents/org.shum.cli.<ID_профиля>.plist"
```

Замените `<ID_профиля>` на ID из имени файла. Если служба уже выгружена, `bootout`
сообщит, что она не найдена; файл всё равно можно удалить. При отсутствии
бинарника `RunAtLoad` может дать ошибку при входе, но `KeepAlive=false` не создаёт
бесконечного цикла запусков. После выгрузки всех служб можно удалить только
кэш `services` в их каталогах данных, сохранив остальные файлы.

### Команды

```sh
shum profile
shum profile list
shum profile use 'PROFILE_ID'
shum profile name "Новое имя"
shum profile bio "О себе"
shum profile avatar --random
shum qr
shum add 'shum://c4/…'
shum add --image ~/Desktop/invite.png
shum contacts
shum invite 'ID_контакта'
shum accept 'ID_контакта'
shum chats --invites
shum chats --unread
shum send 'ID_контакта' "Привет"
shum open 'ID_контакта'
shum ui 'ID_контакта'
shum keys verify 'ID_контакта'
shum keys verify 'ID_контакта' --qr
shum react <ID-сообщения> like
shum clear 'ID_контакта' --confirm
shum lock
shum unlock
shum status --json
```

`add` сохраняет карточку. `invite <ID>` отправляет запрос на чат; `send`
доступен после принятия. Подтверждение команды отправки означает запись
в зашифрованную очередь. `forwarding` означает принятие релеем, `delivered`
и `read` появляются только по подписанному ACK собеседника.
Команды контактов принимают полный Shum ID, его уникальный префикс от 8
символов или полный сетевой ID (публичный Nostr-ключ, 64 символа lowercase hex).
`shum profile` показывает оба ID своего профиля; `shum contacts` показывает ID
сохранённых контактов. `shum invite <сетевой-ID>` для нового контакта запрашивает
и проверяет подписанную карточку, затем отправляет приглашение. Собеседник
должен ответить в течение 20 секунд. Полная карточка или QR добавляются офлайн.

Реакции v1: `heart`, `like`, `dislike`, `laugh`, `fire`, `coffin`, `hundred`, `horror`.

В TUI: 1–4 фильтры, стрелки или j/k для списка, Enter открыть/отправить,
Tab список/ввод, Esc из поля к списку, PgUp/PgDn история, Ctrl+P профили,
Ctrl+N рядом, i мой QR, a добавить, q выйти из списка. Клавиши i/q/a/j/k
работают и в русской раскладке. В поле сообщения буквы вводятся как текст.
Ctrl+C, Ctrl+Q и F10 выходят из любого окна TUI, в том числе во время
ожидания c2/службы. Несохранённый текст остаётся при Esc к списку.
Поддерживаются мышь и вставка текста. Командная строка открывается `/` и
всегда видна, `/help` открывает отдельное окно справки.

В открытом чате `/invite`, `/accept`, `/decline`, `/read` и `/clear` действуют
на его собеседника без аргумента. Вне чата нужен ID. `/qr` или клавиша i
показывают собственный QR. Имена контактов используются только для отображения.

Примеры внутри TUI: `/invite`, `/invite <ID>`, `/qr`,
`/add <ссылка>`, `/add --image "путь.png"`, `/accept [ID]`, `/decline [ID]`,
`/open <ID>`, `/send <ID> "Привет"`, `/read [ID]`, `/clear [ID]`
с подтверждением, `/profile name Новое имя`, `/profile avatar --random`,
`/react <ID> <реакция>`, `/cancel <ID>`, `/block <ID> [--undo]`,
`/status`, `/quit` или `/exit`.
Повторная одинаковая реакция снимает её, `cancel` убирает сообщение из очереди.
На маленьком экране QR использует существующий формат c2 и требует,
чтобы служба этого профиля оставалась в сети.

Аватары рисует клиент: PNG в поддерживаемых терминалах, фон ячеек
в Terminal. В ASCII они скрыты. Полный непрозрачный Swift-рендерер остаётся
отдельно для проверки контрактных пикселей.

`lock` останавливает службу и запрещает автоматический запуск до `unlock`.
Это блокировка сеанса, отдельного PIN или пароля CLI пока нет. Ключи
защищает системное хранилище либо права файла. `keys verify` показывает
отпечаток iPhone (12 hex) и полные отпечатки ключей. Общего числового кода
пары из макета в iPhone v1 нет; расхождение записано в spec/02.

Настройки сохраняются в зашифрованной базе профиля:

```sh
shum --relay wss://nostr.oxtr.dev --relay wss://soloco.nl status
shum --push-url off status
```

По умолчанию используются четыре релея из iOS и тот же push API. Не задавайте
`--push-url off`, если нужны уведомления на iPhone. Если Yandex Cloud
блокируется VPN, выключите VPN для проверки; CLI не привязан к `en0`.

`shum status` и `/status` в TUI показывают результат последнего push-запроса:
отправляется, принят сервером или ошибка. Принятие сервером не подтверждает
доставку через APNs: текущий сервер отвечает HTTP 202 даже при отсутствии
токена получателя или отказе Apple. Этот участок проверяется по журналу сервера.
В `shum --json status` поле `pushLast` содержит `eventId`, `state`, `updatedAt`
и ошибку завершённого запроса. Результат хранится до перезапуска службы.
У исходящих сообщений `nostrAccepted` означает принятие релеем,
а `pushScheduled` означает, что очередь выдала действие push, без подтверждения HTTP.

Удалять только ненужный профиль, подтверждая его имя:
`shum profile delete 'PROFILE_ID' --confirm Test`. ID берётся из
`shum profile list`, имя только подтверждает удаление выбранного профиля.
В следующем выпуске имена локальных профилей могут совпадать; выбор, открытие
через `-p` и удаление используют полный ID.

## CI

Workflow запускается только вручную через `workflow_dispatch`.
Push и pull request автоматически ничего не запускают. Проверки выполняются
на macOS, Linux и Windows. Для доступа к Git-зависимостям workflow поддерживает
read-only deploy keys `CORE_DEPLOY_KEY` и `PROTOCOL_DEPLOY_KEY` в Actions secrets
Shum-CLI. Ключи не хранятся в исходниках.

## Сценарии приёмки

Сценарии 4–5 и Bluetooth на macOS доступны для ручной проверки.
Автоматические результаты указаны выше; полная проверка с настоящим iPhone
остаётся обязательной. Фото и сценарий 7 описывают будущую приёмку.

### Этап 4: интернет и iPhone

1. В CLI выполнить `shum init`, задать имя. Проверить `shum profile`,
   `shum profile list`, `shum status` и их варианты с `--json`/`--ascii`.
2. Выполнить `shum qr`, отсканировать QR на iPhone, сохранить контакт.
   Добавить карточку iPhone через `shum add`, затем отправить
   приглашение командой `shum invite <ID>`.
   Принять на iPhone. Проверить состояния приглашения с обеих сторон.
3. На другом CLI-профиле (`shum init -p second`) выполнить
   `shum add <ссылка-с-iPhone>` или `shum add --image <png>`.
   Отправить приглашение с iPhone, проверить `shum chats --invites`,
   выполнить `shum accept <ID>`. Сохранение контакта само не принимает чат.
4. Выполнить `shum open <ID>`, отправить сообщения в обе стороны.
   Проверить отметки доставки, прочтения, набор текста и реакции;
   при выключенном CLI дождаться доставки после повторного запуска.
5. Сменить имя и пиксельный аватар на iPhone, затем в CLI. Убедиться,
   что контакт получает новые профили, а старые сообщения сохраняют снимки.
6. Очистить чат на iPhone, проверить результат в CLI по правилам v1.
   Сверить `shum keys verify <ID>` с отпечатком в настройках
   безопасности профиля телефона. Очистка в CLI локальная по правилам v1.
7. Проверить `contacts`, фильтры `chats`, переключение профиля, `lock`,
   `daemon --install`, `daemon --stop`. Удаление профиля проверять на
   отдельном тестовом профиле с подтверждением его именем.

### Этап 5: TUI

1. Запустить `shum` в терминале. Сверить с макетами 10 и 11: статус,
   вкладки 1–4, аватары, переписка, ввод, подсказки клавиш.
2. Проверить стрелки, `j`/`k`, Enter, Esc, Tab, PgUp/PgDn, `q`, мышь,
   `Ctrl+P`, `Ctrl+N` и командную строку `/`.
3. Выполнить `shum ui <ID>`, отправить и получить сообщение с iPhone.
   Убедиться, что поступающие сообщения обновляются без потери ввода.
4. Проверить терминал с изображениями, вариант `▀▄`, режим `--ascii`.
   При перенаправлении `shum > output.txt` TUI открываться не должен.

### Этап 6: Bluetooth

1. На macOS включить Bluetooth на компьютере и iPhone, разрешить доступ.
   Открыть Shum на iPhone, выполнить `shum --bluetooth status`, затем
   `shum` и Ctrl+N. Оба устройства должны видеть друг друга. Команда
   `shum nearby --json` показывает состояние радио и найденные карточки.
2. Выполнить `shum invite <ID>` для человека рядом, принять приглашение.
   Выключить интернет на обоих устройствах, оставить Bluetooth.
3. Отправить сообщения в обе стороны, проверить отметки, повторы и
   примерное изменение расстояния при приближении и удалении телефона.
4. **Пока недоступно:** `shum profile avatar --photo <файл>`. Фото должно быть видно
   только рядом. После отключения Bluetooth через релей передаётся
   пиксельный аватар, фотография не отправляется.
5. Проверить отказ в разрешении, Linux без прав, сервер без адаптера.
   Интернет-переписка должна оставаться доступной.

### Следующий этап: устройства и v1 stable

Это будущая приёмка после определения форматов в Shum-Protocol и реализации
в Shum-Core. Команды `link`, `unlink` и `sync` пока недоступны.

1. Создать профиль на любом клиенте, привязать второй по QR и сверить код
   на обоих устройствах. Ключи профиля общие; ключи устройств отдельные.
2. Проверить доставку всем привязанным устройствам, синхронизацию прочтения,
   настроек и релеев. После отвязки устройство не получает новые сообщения.
3. Выполнить ручную синхронизацию истории по Bluetooth; проверить очистку
   «здесь» и «на всех устройствах».
4. Проверить перенос существующего профиля без изменения Shum ID и потери
   переписки, одну карточку профиля рядом и правила расширения форматов.

## Ограничения работ

Текущие байты черновика v1 сохраняются до согласования новых форматов и
тестовых примеров v1 stable. Обновление документов само по себе не меняет wire-формат.
Код iOS-приложения не редактируется; новые Swift
генераторы добавляются только в `ShumTests/Protocol`. Запуск разрешён только
для этих тестов на симуляторе iPhone 17 Pro
`9374725C-1A19-4568-A06B-AAB02E8DBCD2`. Коммиты в Shum-iOS требуют
отдельного согласия. Установка Rust и любые загрузки, кроме cargo-зависимостей,
требуют согласия пользователя.
