# Установка и распространение CLI

Обычная установка должна использовать готовые бинарники. Пользователь выбирает
установщик или пакетный менеджер. Сборка из исходников остаётся отдельным способом
для разработчиков.

## macOS

`scripts/package_macos.py` создаёт:

* установщик `.pkg`, который кладёт `Shum.app` в `/usr/local/libexec/shum`,
  а в `/usr/local/bin/shum` создаёт ссылку на бинарник внутри бандла;
* универсальный архив `shum-macos-universal.tar.gz` с подписанным `Shum.app`
  для Homebrew и установки скриптом;
* формулу `dist/homebrew-shum/Formula/shum.rb`;
* SHA-256 и JSON с версией, обеими архитектурами и минимальной macOS каждой.

Пакет не меняет `.zshrc`, профили или переписку. В нём нет установочных скриптов.
После установки достаточно открыть терминал и выполнить `shum`.
Если раньше использовалась установка через Cargo, `command -v shum` может показывать
старую копию из `~/.cargo/bin`. Установщик не удаляет её автоматически.

Сборка на Mac:

```sh
python3 scripts/package_macos.py
```

Или упаковка уже проверенного бинарника:

```sh
python3 scripts/package_macos.py --binary /путь/к/shum-universal
```

Целевая платформа: **macOS 15+, Apple Silicon и Intel**. Сборка выполняет Cargo
для `aarch64-apple-darwin` и `x86_64-apple-darwin`, затем `lipo -create` и подпись
единственного универсального бинарника внутри Shum.app. Цели должны быть установлены
заранее; скрипт не загружает Rust toolchain. Перед загрузкой Intel-цели согласуйте:

```sh
rustup target add x86_64-apple-darwin
```

Для C-зависимостей (secp256k1, zlib, sqlite) задаётся deployment target 15.0;
cc-rs получает архитектуру от Cargo. Закреплённый build.rs ядра вызывает Swift без
cross-target: временный адаптер `xcrun` добавляет соответствующий Swift `-target`
для встроенного CoreBluetooth-помощника. Исходники ядра и Cargo cache не изменяются.

Проверяется Mach-O каждого среза CLI и его встроенного Bluetooth-помощника:
архитектуры совпадают, максимальный minimum OS равен 15.0.0, динамические библиотеки
только системные. Формула не ограничена arm64; один и тот же архив используется
на обеих архитектурах. Проверка на настоящем Intel Mac пока не проводилась.
Под Rosetta прошли Intel CLI --version и релейный сценарий с приглашениями,
сообщениями, квитанциями и сохранением очереди при перезапуске. Rosetta на Apple
Silicon не заменяет настоящий Intel Mac. Windows и Linux не собирались.

Проверка пакета без установки:

```sh
python3 scripts/verify_macos_package.py dist/Shum-CLI-0.1.6-macOS-universal-unsigned.pkg
```

## Homebrew

Публичный tap: [hiTechTeam/homebrew-shum](https://github.com/hiTechTeam/homebrew-shum).
Формула 0.1.6 устанавливает `Shum.app` в `prefix`, создаёт ссылку
`bin/shum`, проверяет SHA-256 и версию:

```sh
brew install hitechteam/shum/shum
brew update
brew upgrade shum
```

Бинарник и установщик доступны в [Releases](https://github.com/hiTechTeam/homebrew-shum/releases).
Shum-Core подключается как отдельная закреплённая Git-зависимость. Публичный tap содержит формулу,
инструкцию и готовые артефакты. Автоматический CI выключен.

При подготовке нового выпуска скрипту нужно передать `--release-base-url` с HTTPS-адресом
каталога артефактов вида `https://github.com/hiTechTeam/homebrew-shum/releases/download/vVERSION`.
Сначала загрузите артефакты, затем обновите формулу. Опубликованные версии и их SHA-256
не заменяются: исправления выходят отдельной версией. Без `--release-base-url`
формула ссылается на локальный `file://` архив и не пригодна для публикации.

## Установка скриптом

`install.sh` написан на POSIX sh, без sudo, изменения shell-файлов и установки
инструментов разработчика. Команда установки и обновления:

```sh
curl -fsSL https://raw.githubusercontent.com/hiTechTeam/Shum-CLI/main/install.sh | sh
```

Архив и `shum-macos-universal.tar.gz.sha256` загружаются из
`https://github.com/hiTechTeam/homebrew-shum/releases/latest/download`.
Имя файла стабильно, версия находится в бандле и манифесте. Формула использует
тот же файл в каталоге конкретного выпуска `releases/download/vVERSION`;
опубликованные артефакты конкретной версии не заменяются.

Установщик отказывается ставить вторую копию рядом с Homebrew и не перезаписывает
чужую команду `~/.local/bin/shum`. Перед установкой проверяет SHA-256, содержимое
архива без ссылок, подпись org.shum.cli с закреплённым сертификатом, обе архитектуры
через codesign, версию бинарника и Info.plist. `lipo` нужен при сборке, а пользователю
не требуется. Ошибка проверки сохраняет работающую установку.

Бандлы находятся в `~/.local/share/shum/versions/<archive-SHA256>/Shum.app`.
Стабильная ссылка `~/.local/share/shum/Shum.app` переключается атомарно, а
`~/.local/bin/shum` ссылается на бинарник внутри неё. LaunchAgent использует
стабильный путь, без номера версии. После обновления внутренний вызов
`shum daemon --refresh` мягко заменяет активные службы; неактивные профили не открываются.
Предыдущие бандлы остаются целыми, даже пока старый процесс завершает работу.

Для обновления повторите команду установки. Для удаления сохранённым скриптом:

```sh
sh install.sh --uninstall
```

Сначала удаляются службы командой `shum daemon --uninstall`, затем принадлежащие
установщику файлы и ссылка в `~/.local`. Повтор безопасен. Данные профилей остаются
в `~/Library/Application Support/org.Shum.Shum`, других `--data-dir` и Keychain.
Порядок ручной очистки после удаления бинарника описан ниже. Не удаляйте данные,
если хотите сохранить ключи и переписку.

Публикация install.sh в main, нового универсального выпуска и обновление tap
выполняются только после согласия владельца. До этого URL нового скрипта и
стабильные assets могут быть недоступны.

## Остальные менеджеры

В макете загрузок предусмотрены winget для Windows, apt для Debian/Ubuntu и dnf для
Fedora. Для фактической поддержки нужны проверенные бинарники соответствующих ОС,
пакеты и публикация в каталогах или репозиториях. Эти способы пока не реализованы.
Наличие карточки в Figma не означает доступность пакета.

## Публичный выпуск

Приложение подписывается самоподписанным сертификатом `Shum CLI Signing`
с идентификатором `org.shum.cli`. Отсутствие сертификата останавливает сборку;
ad hoc подпись не подставляется автоматически. Требование подписи явно закреплено
за SHA-1 публичного сертификата, без `cdhash` исполняемого файла.
[Создание сертификата и проверки](macos-signing.md).

Контейнер `.pkg` без Developer ID Installer помечается `-unsigned`, даже когда
`Shum.app` внутри подписан локальным сертификатом. Опция `--sign-installer`
подписывает только установщик. Самоподписанная подпись не является Developer ID,
не делает сертификат доверенным на чужих Mac и не заменяет нотарификацию.
Нотарификация и автоматическое изменение системного доверия не выполняются.
Запуск без предупреждений Gatekeeper на чистой учётной записи поэтому не обещается.
[Apple: Developer ID](https://developer.apple.com/developer-id/) и
[проверка загруженных приложений](https://support.apple.com/en-us/102445).

Для локальной проверки скрипта доступен `--development-adhoc`; с
`--release-base-url` он запрещён. Такой артефакт нельзя выпускать как пакет со
стабильной сертификатной подписью.

Удаление: сначала `shum daemon --uninstall`, затем `brew uninstall shum`.
Формула сообщает этот порядок одной строкой caveats. Данные сохраняются.
Каталог macOS: `~/Library/Application Support/org.Shum.Shum`. В следующем выпуске
для полного стирания предусмотрена команда `shum daemon --uninstall --purge`,
с подтверждением `DELETE` (для скриптов: `--confirm DELETE`). Она удаляет
профили штатным способом, включая ключи в Keychain, и очищает реестр и кэш служб.
Без `--data-dir` обрабатываются стандартный каталог и корни из LaunchAgents;
с явным каталогом удаляются только его данные Shum. Посторонние файлы сохраняются,
команда сообщает, что каталог не удалён полностью. Пакет удаляется отдельно:
`brew uninstall shum` или скриптом установки. В 0.1.6 режима purge ещё нет:
сначала удалите каждый профиль через `shum profile delete`, затем службы, пакет
и остатки каталога данных.
Если формула уже удалена, выгрузите каждый `org.shum.cli.<UUID>.plist` через
`launchctl bootout gui/$(id -u) /полный/путь/к/файлу.plist`, затем удалите файл.
`KeepAlive=false` исключает бесконечный перезапуск при отсутствующем бинарнике.

Скрипт ничего не публикует и не включает CI. Архивы `dist` исключены из Git.
